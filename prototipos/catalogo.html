Catálogo de servicios

Aplicaciones al alcance de cualquier funcionario

Un servicio es una pantalla construida sobre una o más APIs del catálogo, que resuelve una tarea concreta. No hay que instalar nada ni escribir código: se entra, se busca y se usa.

Es la contracara del catálogo de APIs. Aquel dice qué se puede consumir desde un sistema; este dice qué se puede hacer hoy desde una pantalla. Cada servicio indica sobre qué API está construido, porque quien lo necesite dentro de su propio sistema va a querer llegar a lo mismo por la interfaz.

Cómo crece

Cómo va a crecer la lista

Un servicio solo puede existir cuando la API sobre la que se apoya ya entrega algo. Hoy una sola del catálogo está en ese punto, así que hay un solo servicio. No es una lista incompleta: es el estado real, y va a crecer al ritmo del otro catálogo.

La regla que ordena esto: el servicio no tiene atajos. Consume la misma interfaz pública que usaría el sistema de un municipio o el de un proveedor. Si una pantalla de SUBDERE pudiera llegar a datos que la interfaz no expone, el catálogo de APIs dejaría de describir lo que de verdad se puede construir.
