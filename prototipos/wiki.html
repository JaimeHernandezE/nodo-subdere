Wiki

Cómo se usa esto, y por qué está hecho así

Los catálogos dicen qué hay. Esta wiki dice cómo se usa y por qué está definido de esa manera: desde consumir una API hasta cómo se generan los códigos territoriales y qué norma obliga a cada cosa.

Está separada de los catálogos a propósito. Un catálogo se consulta para encontrar algo; una wiki se lee para entender. Mezclarlos hace que ninguna de las dos cosas funcione bien.

Probar antes de operar

Practicar con datos inventados y trabajar con datos reales son dos situaciones distintas. Lo que el servicio promete es idéntico; cambian los datos y el permiso.

Pendiente de escribir: la guía paso a paso del ambiente de pruebas. Hoy no hay ninguno funcionando.

Versiones y cambios

Cada contrato se registra con versión y ninguna se corrige: si algo cambia, se publica una versión nueva y se sabe cuál rige. Quienes estén conectados reciben aviso con antelación, y la versión anterior sigue funcionando durante un período de gracia. La decisión de fondo está en la nota de arquitectura sobre el estándar legible por máquina.

La entrada de los Códigos Únicos Territoriales muestra el nivel de detalle al que debería llegar cada norma: qué fija, con qué decreto y si se leyó el texto o solo una referencia. Puerta de acceso Nombre provisional

También se le dice Plataforma de Control.

Es el único camino por el que un sistema o una persona llega a una API del catálogo. Comprueba quién llama, cuánto puede pedir y deja constancia.

Tiene dos partes. Una sabe quién es cada municipio o sistema y le entrega un permiso temporal. La otra revisa ese permiso en cada llamada, limita cuánto se puede pedir y lo anota. Las personas entran con Clave Única y los sistemas con una credencial del municipio; los dos pasan por aquí, y nadie tiene atajos.

No decide nada del contenido: validar lo que se envía, devolver observaciones y emitir el comprobante lo hace cada servicio. Tampoco es la base común del SGM: esa es la base del sistema, esta controla quién llama.

Por qué está definido así

Las decisiones que dan forma al estándar están escritas como notas fechadas, con su contexto y sus consecuencias. No se corrigen: si una decisión cambia, se escribe una nueva que la reemplaza y se deja dicho cuál rige.
